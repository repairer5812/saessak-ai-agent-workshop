## 2.5 운영 TIP: 순서를 뒤집어도 된다 (데이터 먼저)
문제를 먼저 정의하고 데이터를 찾는 '문제 → 데이터' 방식은 실제 수업에서 막힐 때가 많다. 학생이 정한 문제에 맞는 공공데이터가 없거나 지저분해서 진도가 멈추기 때문이다.
그래서 **'데이터 → 문제'로 뒤집어 운영**할 수 있다: 먼저 공공데이터포털에서 우리 동네 관련 '실제로 있고 깨끗한' 데이터를 둘러보고, 그 안의 눈에 띄는 패턴(가장 큰 값, 갑자기 변한 값, 이상치)에서 "왜 이렇지?" 하는 문제를 발견한다. 시작부터 분석 가능한 데이터가 손에 있어 수업이 훨씬 수월하다.
- 두 방향 모두 가능하니 학급 상황에 맞게 고른다. 막히는 모둠만 '데이터 먼저'로 전환해도 된다.
- 이 두 방향은 **데이터 사냥꾼 새봄**(주)과 **공감이**(보조) 에이전트가 안내하도록 설계돼 있다.

## 2.6 운영 TIP: 강사가 예시 에이전트를 미리 만들어 시연하기
강사는 수업 전에 '에이전트 만들기 좋은 데이터'를 미리 찾아 두고, 예시 에이전트를 직접 하나 만들어 학생에게 시연하는 것이 중요합니다. 학생은 완성된 예시를 직접 보고 만져 봐야 '나도 만들 수 있겠다'는 감을 잡습니다.

**에이전트 만들기 좋은 데이터의 조건**
- 우리 동네·관심사로 좁혀지는 데이터
- 표(CSV)처럼 비교·검색이 되는 형태
- 항목이 명확한 숫자·범주(가격·면적·개수 등)
- 개인정보가 없음
- 수십~수백 행의 적당한 크기

아래 3장의 예시 에이전트 6종, 그리고 강사 시연용 완성작(월세 비교 에이전트)이 그 본보기다. 강사는 수업 전 이런 예시를 미리 만들어 두고, 학생에게 "이런 걸 만드는 거예요"라고 직접 시연한다.

## 2.7 Gem 액션(기능) 활용 (API 통신 아님)
Gemini Gem은 외부 API 통신은 못 해도 내장 액션을 켤 수 있다. **자동 동작**: Google 검색 그라운딩, Knowledge files. **기본도구 드롭다운(1개 선택)**: 이미지 생성, Canvas, Deep Research, 음악 생성, Guided Learning. Canvas를 켜면 그 안에서 Python 코드 실행 가능. (Deep Research 비주얼 리포트는 Google AI Ultra 전용, 텍스트는 무료·Pro 가능)

- **🔎 Google 검색 그라운딩 (Google Search grounding)**: 답변할 때 실시간 구글 검색으로 최신 웹 정보를 끌어와 사실을 보강하고 출처를 표시. Gem 빌더에 전용 토글이 없고 모든 Gem이 기본 모델로부터 자동 상속(별도 켜기 불필요).  · _교실: 우리 동네 인구·교통·생활 통계, 최신 공공데이터포털 링크, 전국 단지 시세 등 업로드 자료에 없는 사실을 Gem이 스스로 검색해 채움. 새봄·지킴·방방이의 토대._
- **🖼️ Canvas (캔버스)**: 글·코드를 Gemini와 나란히 작성·편집·미리보기 하는 인터랙티브 작업공간. 코드를 생성하고 그 자리에서 실행·미리보기 가능. Gem 생성 시 'Default tool(기본 도구)' 드롭다운에서 선택하면 모든 대화가 캔버스로 시작.  · _교실: 또렷의 발표 대본·슬라이드 초안, Master의 수업 안내문, 셈셈의 함수 계산 과정을 한 화면에서 보여주고 바로 고쳐 쓰기._
- **🧮 코드 실행 (Canvas 내 Python 실행)**: Gemini가 Python을 작성해 샌드박스에서 실행, 계산·데이터 처리·검증. Gem에는 '코드 실행' 단독 토글이 없고 Canvas를 기본 도구로 켜면 캔버스 안에서 코드 생성·실행이 동작.  · _교실: 셈셈이 SUM/AVERAGE/COUNTIF/FILTER가 실제로 어떤 결과를 내는지 학생 표 데이터로 직접 계산해 보여주며 함수 원리를 검증._
- **📚 Deep Research (딥 리서치)**: 여러 웹사이트를 자동 탐색해 조사 계획 후 출처·인용 포함 종합 리포트를 생성. 기본 도구 드롭다운에서 선택하면 모든 대화가 리서치 모드로 시작. (단 차트·이미지·시뮬레이션이 들어간 '비주얼 리포트'는 Google AI Ultra 유료 전용)  · _교실: 방방이가 특정 동네 전월세 흐름을 여러 출처로 종합하거나, 새봄이 주제별 공공데이터 소스를 폭넓게 모아 출처와 함께 정리._
- **🎨 이미지 생성 (Create image, Imagen·Nano Banana)**: 텍스트→이미지 생성·편집(Imagen 4 / Nano Banana 계열). 기본 도구 드롭다운에서 선택하면 모든 대화가 이미지 생성 모드로 시작.  · _교실: 지음이 Gem 페르소나 캐릭터·아이콘, 또렷의 발표 슬라이드용 삽화, 팀 프로젝트 포스터 시안을 즉석에서 생성._
- **🧭 Guided Learning (가이드 학습)**: 정답을 바로 주지 않고 단계적 질문·힌트로 학생이 스스로 깨닫게 하는 학습 튜터 모드. 기본 도구 드롭다운에서 선택.  · _교실: 공감이가 학생에게 동네 불편함을 질문으로 떠올리게 유도하고, 셈셈이 함수 원리를 소크라테스식으로 캐묻는 데 활용._
- **📎 Knowledge files (지식 파일)**: 문서·표·PDF를 Gem에 첨부(기기 업로드 또는 Google Drive 연결)하면 모든 대화에서 영구 참조. 인용 표시 on/off 토글 별도. Gem 고유의 핵심 기능.  · _교실: 방방이에 우리 반이 수집한 전월세 표본, 새봄에 추천 데이터셋 목록, Master에 12차시 수업안을 붙여 일관된 근거로 답하게 함._
- **🎵 음악 생성 (Create music, Lyria)**: 텍스트 프롬프트로 짧은 음악·오디오를 생성. 기본 도구 드롭다운에서 선택.  · _교실: 또렷의 발표 오프닝 BGM, 팀 캠페인 영상 배경음 등 부가 자료. 핵심 6종 외 선택지로 안내._

에이전트별 추천 액션은 3장 각 카드의 'Action'에 반영돼 있다: 공감이=Guided Learning, 새봄·지킴·방방이=Google 검색 그라운딩+Knowledge, 셈셈=Canvas(코드 실행), 지음=이미지 생성, 또렷=Canvas+이미지, Agent Master=Canvas+Knowledge. **방방이는 표본에 없는 전국 지역을 Google 검색 그라운딩으로 자동 보강**한다(출처·조회시점 명시, 정밀 전국은 data.go.kr 활용신청 CSV로 확장).

### 7~8차시 'Gem 액션 선택·켜기' 반영
12차시 흐름(1~2 공감·데이터 탐색 / 3~4 시트 함수 / 5~6 페르소나·윤리 기획 / 7~8 Gem 제작 / 9~12 발표·시연)에서 'Gem 액션(기능) 선택·켜기'는 7~8차시에 정식 단계로 넣되, 앞 차시에 미리 씨앗을 뿌립니다.

[사전 노출(5~6차시)] 페르소나·윤리 기획서를 쓸 때 마지막 칸에 '이 Gem이 일하려면 어떤 기능이 필요할까?'를 적게 합니다. 예: 시세 비교 → 검색, 캐릭터 → 이미지, 계산 → 코드/캔버스. 기능을 '도구 카드'로 미리 손에 쥐게 하는 것.

[7차시 — 기능 고르기] (a) 도입 10분: 강사가 Gem 빌더의 'Default tool(기본 도구)' 드롭다운 6개(No default tool / Create image / Canvas / Deep Research / Create music / Guided Learning)와, 토글 없이 자동 동작하는 2가지(Google 검색 그라운딩, Knowledge files)를 화면으로 시연. '핵심 액션 카드' 7장(검색·Canvas·코드실행(캔버스)·Deep Research·이미지·Guided Learning·Knowledge)을 배부. (b) 활동 20분: 팀이 자기 에이전트의 역할에 맞춰 '기본 도구 1개 + 자동 기능(검색/지식파일) 체크'를 결정해 워크시트에 적습니다. 의사결정 규칙을 제시: 매 대화가 같은 모드로 시작해야 하면 그 도구를 기본 도구로 켜고(예 셈셈=Canvas, 지음=이미지), 사실 보강은 검색 그라운딩이 자동이라 따로 안 켜며, 참고 자료는 Knowledge에 파일로 붙인다. (c) 검증 15분: '기능-역할 매칭 점검표'로 짝팀끼리 교차 검토(예: 공감이가 이미지를 기본으로 켰다면 '공감 단계에 그림이 꼭 필요한가?' 되묻기).

[8차시 — 실제로 켜고 만들기] (a) 빌더 실습 25분: 7차시에 정한 대로 Name·Description·Instructions를 채우고, 'Default tool' 드롭다운에서 결정한 도구를 선택, Knowledge에 팀 데이터 파일 첨부, 저장. 방방이 팀은 표본 표를 Knowledge로 붙이고 '표에 없으면 검색, 출처 명시' 지침을 넣는 시연을 따라 합니다. (b) 즉시 테스트 15분: 각 도구가 의도대로 켜졌는지 확인하는 '3문제 테스트'(셈셈에 계산 1개, 새봄에 데이터 검색 1개, 지음에 이미지 1개)로 실제 동작을 눈으로 검증. (c) 한계 토의 5분: '검색은 실시간이지만 시세 DB가 아니다', 'Deep Research 비주얼 리포트는 유료(Ultra)다' 같은 한계를 짚어 데이터 신뢰성·출처 확인 가치까지 학습으로 연결. 

[강사 지원] Agent Master Gem을 8차시 보조 강사로 띄워, 학생 질문('우리 Gem에 어떤 기능 켜야 해요?')에 Master가 Knowledge에 붙은 이 매칭 가이드대로 답하게 합니다. 단, 기본 도구 드롭다운 항목은 계정·버전에 따라 노출이 달라질 수 있으니(공식 support 문서엔 드롭다운 목록 자체가 미명시), 수업 전 강사 계정에서 실제 드롭다운을 한 번 캡처해 학생 화면과 맞춰 두는 사전 점검을 권장합니다.

**Gems 지시문**
```
# 역할(Role)
너는 '공감이'야. 중학생이 우리 동네에서 느낀 불편함을 스스로 떠올리고, 그 문제를 '느끼는 사람'의 눈으로 깊이 이해하도록 돕는 디자인씽킹 공감 코치야. 친근하고 다정한 반말 섞인 존댓말(예: '좋은 생각이에요!')로 답해. 너의 목표는 학생이 답을 받는 게 아니라, 스스로 자기 동네 문제를 발견하게 하는 거야.

# 지식 활용(Knowledge)
```

```
# 답변 규칙(소크라테스식, 가장 중요)
1) 학생이 '합계 어떻게 구해요?' '함수 알려 주세요'라고 하면, 함수식을 바로 주지 말고 먼저 되물어: '합계는 "여러 칸의 숫자를 하나로 더하는 것"이지? 손으로 한다면 어떤 칸들을 더해야 할까?'
2) 학생이 더할 범위를 스스로 말하면, 그제서야 '그걸 컴퓨터에게 시키는 함수 이름이 SUM이야. 괄호 안에 그 범위를 넣어 보면 어떨까?'처럼 한 칸씩 비계를 줘. 완성식은 학생이 직접 쓰게 해.
3) 함수별 원리 질문 가이드:
 - SUM: '하나하나 더하는 것을 한 번에 하면?'
 - AVERAGE: '합계를 "개수"로 나누면 무엇이 나올까? 그게 왜 평균일까?'
 - COUNTIF: 'IF는 "만약"이라는 뜻이야. COUNT(세기)에 "만약 ~라면"을 붙이면 무엇을 셀 수 있을까? 도담초 정문이 몇 번 나오는지 세고 싶다면?'

4) 학생이 틀린 식을 쓰면 '틀렸어'라고 하지 말고, '거의 다 왔어! 괄호 안 범위를 다시 한번 볼까? 어디까지가 사고건수 칸일까?'처럼 스스로 고치게 유도해.
5) 3번 이상 헤매면 그때만 정답 식을 보여 주되, 반드시 '왜 이렇게 되는지' 한 줄 설명을 붙여.
6) 어떤 차트가 어울리는지 물으면: '숫자 비교는 막대, 시간 흐름은 꺾은선, 비율은 원형이야. 우리 데이터로 "어디가 제일 위험한가"를 보여 주려면 무엇이 좋을까?'
7) 답변은 5문장 이내, 한 번에 질문 1개.
```

## 4. 데이터 전처리 scaffolding (Google Sheets 안 Gemini)
**왜 어려운가**: 중학생은 함수를 처음 배우기 때문에, 공공데이터포털에서 받은 원본 파일이 한 화면에 깔끔하게 정리돼 있을 거라 기대하지만 실제로는 빈칸(결측치), 말도 안 되게 큰 값(이상치), '서울특별시'와 '서울시'처럼 같은 뜻인데 다르게 적힌 표기, '2023-05-01'과 '2023.5.1'처럼 뒤섞인 날짜 형식이 한꺼번에 들어 있습니다. 어디가 잘못됐는지 눈으로 한 줄씩 찾는 것 자체가 오래 걸리고, 빈칸을 0으로 채워야 할지 평균으로 채워야 할지 같은 판단이 어렵습니다. 또 함수 이름과 괄호 안 인자 순서를 외워야 하고, 글자 표기를 통일하려면 TRIM, SUBSTITUTE 같은 낯선 함수를 조합해야 해서 한 셀만 틀려도 그래프 전체가 이상해집니다. 데이터가 7개 컬럼 곱하기 수십 행이라 손으로 다 고치다 보면 분석·디자인씽킹이라는 진짜 활동에 쓸 시간이 사라집니다. 그래서 무엇이 문제인지 찾아 주고, 어떤 함수를 어떤 순서로 쓰면 되는지 옆에서 알려 주는 비계(scaffolding)가 필요합니다.

**핵심 전략 (두 갈래 길)**
- ① Gemini 사이드패널 채팅: 시트 우측 Gemini 채팅창에 말로 부탁 (모든 학교 계정에서 1차 경로)
- ② `=AI()` 함수: 셀에 직접. 학교 계정에 따라 안 보일 수 있으니 **수업 전 강사가 표시 여부 반드시 확인**

**시트에서 Gemini 켜기**
- Google 계정으로 로그인한 뒤, 모둠이 정리할 공공데이터를 Google Sheets에 업로드합니다. (드라이브에 올린 CSV/XLSX를 더블클릭하고 'Google 스프레드시트로 열기')
- 화면 오른쪽 위의 별 모양(또는 'Gemini') 아이콘을 눌러 Gemini 사이드패널을 엽니다. 패널이 안 보이면 상단 메뉴 '도구 > Gemini' 또는 확장 프로그램 영역에서 Gemini를 켭니다. (학교 계정은 관리자가 Gemini를 켜 둬야 보입니다. 안 보이면 강사에게 요청)
- 사이드패널이 열리면 아래 입력창에 우리말로 부탁을 적습니다. 예: '이 시트에서 빈칸이 있는 행을 모두 찾아 줘'. Gemini가 어떤 셀이 비었는지, 어떤 함수를 쓰면 되는지 알려 줍니다.
- 셀 안에서 직접 AI를 쓰려면 빈 셀에 '=AI(' 를 입력합니다. 표기 통일·요약 같은 작업을 함수처럼 쓸 수 있습니다. (=AI 함수는 계정·지역에 따라 'AI', 'AI.TABLE' 등으로 보일 수 있고, 안 보이면 사이드패널 채팅으로 같은 일을 부탁합니다.)
- =AI 함수가 만든 결과는 추천값일 뿐이므로, 그대로 두지 말고 마우스로 셀을 복사한 뒤 '값으로 붙여넣기(Ctrl+Shift+V)'를 해서 진짜 데이터로 고정합니다. 그래야 그래프와 함수가 흔들리지 않습니다.
- 마지막으로 사이드패널에 '지금까지 무엇을 어떻게 정리했는지 3줄로 요약해 줘'라고 부탁해, 정리 과정을 학습지(데이터 분류 기준 정리표)에 기록합니다.

**전처리에 쓰는 함수**
- `=COUNTBLANK(C2:C11)` : 빈칸(결측치)이 몇 개인지 세어 준다. 원리: 범위 안에서 비어 있는 셀의 개수만 합산한다. (예: 사고건수 열의 결측치 개수를 한 번에 확인: =COUNTBLANK(C2:C11))
- `=COUNTIF(G2:G11,"")` : 특정 조건(여기서는 빈칸)에 맞는 셀을 센다. 원리: 범위에서 조건과 같은 셀만 골라 개수를 센다. (예: 주요사고시간대가 비어 있는 행 수: =COUNTIF(G2:G11,""))
- `=TRIM(SUBSTITUTE(B2,"  "," "))` : 글자 앞뒤·중간의 불필요한 공백을 없애 표기를 통일한다. 원리: SUBSTITUTE로 두 칸 공백을 한 칸으로 바꾸고, TRIM으로 양끝 공백을 제거한다. (예: '도담초 정문  앞 횡단보도'처럼 공백이 섞인 지점명 정리: =TRIM(SUBSTITUTE(B2,"  "," ")))
- `=AVERAGE(C2:C11)` : 평균을 내서 이상치(너무 크거나 작은 값)를 판단하는 기준선을 만든다. 원리: 숫자 값을 모두 더해 개수로 나눈다. (예: 사고건수 평균과 비교해 40 같은 값이 이상치인지 판단: =AVERAGE(C2:C11))
- `=D2=E2+F2` : 사상자수 = 중상자수 + 경상자수 가 맞는지 셀끼리 검산해 논리 이상치를 잡는다. 원리: 두 식의 결과가 같으면 TRUE(참), 다르면 FALSE(거짓)를 돌려준다. (예: 각 행의 합계가 맞는지 한 줄로 검산: =D2=E2+F2 (FALSE가 나오는 행을 다시 확인))
- `=AI("이 텍스트를 표준 시간대 형식 'HH-HH시'로 바꿔 줘. 예: 오후3시->15-16시", G2)` : Sheets 안에서 Gemini를 함수처럼 호출해 들쭉날쭉한 표기를 통일된 형식으로 바꾼다. 원리: 큰따옴표 안 지시문대로 옆 셀(G2) 내용을 AI가 변환해 돌려준다. (예: '오후 3시', '15시경', '15:00'을 모두 '15-16시'로: =AI("이 시간 표기를 'HH-HH시' 형식으로 통일해 줘", G2))
- `=AI("이 지역명을 '시/도 시/군/구' 표준 표기로 정리해 줘. 예: 서울시->서울특별시", A2)` : '서울시/서울특별시'처럼 같은 뜻 다른 표기를 표준 명칭으로 통일한다. 원리: AI가 지시문 기준에 맞춰 셀 값을 다듬어 돌려준다. (예: 지역 표기 통일: =AI("행정구역 표준 명칭으로 바꿔 줘", A2))
- `=AI("이 표의 사고 다발지점 상위 3곳과 가장 위험한 시간대를 중학생이 이해하게 2문장으로 요약해 줘", A1:G11)` : 정리가 끝난 표 전체를 Gemini가 한국어 두 문장으로 요약해, 인사이트 도출과 발표 준비를 돕는다. 원리: 범위 전체를 AI에 넘겨 지시문대로 핵심을 뽑아낸다. (예: 분석 요약 자동 생성: =AI("가장 사고가 많은 지점과 시간대를 2문장으로 요약", A1:G11))

**전처리 5단계 (before → after)**

**1. 빈칸(결측치) 찾아 표시하기**
- 전(지저분): 2번째 행 사고건수가 비어 있고, 5번째 행 사상자수가 비어 있고, 7번째 행 주요사고시간대가 비어 있어 어디가 빠졌는지 눈으로 다 찾기 힘들다.
- 학생이 하는 일: 사이드패널에 빈칸을 찾아 달라고 부탁하고, 알려 준 함수 =COUNTBLANK 와 =COUNTIF 로 각 열에 빈칸이 몇 개인지 센 다음, 빈 셀을 노란색으로 칠해 표시한다.
- 시트 안 Gemini 비계: 사이드패널 프롬프트: '이 시트에서 빈칸이 있는 셀을 모두 찾아 어느 행 몇 번째 열인지 알려 주고, 각 열의 빈칸 개수를 세는 함수도 알려 줘.'
- 후(깨끗): 사고건수 1칸, 사상자수 1칸, 주요사고시간대 1칸이 비어 있다는 것을 모두 찾아내 노란색으로 표시하고, 어디를 채워야 할지 목록으로 정리했다.

**2. 결측치 어떻게 채울지 판단하고 채우기**
- 전(지저분): 사고건수가 빈 행은 0으로 둘지 평균으로 둘지 모르겠고, 사상자수가 빈 행은 중상자수+경상자수로 계산할 수 있는데 방법을 모른다.
- 학생이 하는 일: 빈칸의 의미를 Gemini에게 물어 채우는 기준을 정하고, 사상자수 빈칸은 =E6+F6 처럼 중상자수+경상자수로 계산해 채운다. 사고건수 빈칸은 '값 없음'으로 표시하거나 출처 확인 대상으로 남긴다.
- 시트 안 Gemini 비계: 사이드패널 프롬프트: '교통사고 데이터에서 사고건수가 빈칸일 때 0과 평균 중 무엇으로 채우는 게 맞아? 사상자수는 중상자수+경상자수로 채워도 될까? 중학생도 이해하게 이유와 함께 알려 줘.'
- 후(깨끗): 사상자수 빈칸은 중상+경상 합(2명)으로 채우고, 사고건수 빈칸은 함부로 추측하지 않고 '확인 필요'로 표시해 출처 확인 대상으로 남겼다. 왜 그렇게 정했는지 학습지에 기록했다.

**3. 이상치(말도 안 되는 값) 찾아내고 검산하기**
- 전(지저분): 4번째 행 사고건수가 40으로 다른 행(2~4)보다 터무니없이 크고, 6번째 행은 사상자수 3인데 경상자수가 5라 합계가 안 맞아 어디가 틀렸는지 헷갈린다.
- 학생이 하는 일: =AVERAGE 로 사고건수 평균을 내 40이 평균보다 훨씬 큰 이상치임을 확인하고, =D2=E2+F2 로 사상자수=중상+경상 검산식을 모든 행에 채워 FALSE가 나오는 행을 찾는다.
- 시트 안 Gemini 비계: 사이드패널 프롬프트: '사고건수 열에서 평균보다 비정상적으로 큰 값을 이상치로 찾아 주고, 사상자수가 중상자수+경상자수와 다른 행도 찾아 줘. 각각 어떤 함수로 검사하는지도 알려 줘.'
- 후(깨끗): 사고건수 40은 4로 잘못 입력된 이상치로 보고 출처 확인 후 4로 수정 표시하고, 사상자수 합계가 안 맞는 행(경상자수 5는 3의 오타로 추정)을 찾아 빨간색으로 표시해 다시 확인 대상으로 남겼다.

**4. 표기 불일치 통일하기 (지점명·연도)**
- 전(지저분): 1행과 2행 지점명이 '도담초 정문 앞 횡단보도'와 '도담초 정문  앞 횡단보도'(공백 차이)라 다른 곳처럼 집계되고, 발생연도가 '2023', '2023년', '2022.07.01'로 뒤죽박죽이다.
- 학생이 하는 일: 지점명은 =TRIM(SUBSTITUTE(...)) 로 공백을 정리해 같은 지점끼리 표기를 맞추고, 발생연도는 =AI 함수로 모두 4자리 숫자 연도로 통일한 뒤 값으로 붙여넣기 한다.
- 시트 안 Gemini 비계: 셀 함수: =AI("이 값에서 연도만 뽑아 네 자리 숫자로 바꿔 줘. 예: 2023년->2023, 2022.07.01->2022", A2)  /  사이드패널: '지점명 표기가 공백 때문에 다르게 잡히는 행을 같은 이름으로 묶어 줘.'
- 후(깨끗): '도담초 정문 앞 횡단보도'가 한 가지 표기로 통일돼 같은 지점으로 정확히 집계되고, 발생연도가 모두 2021·2022·2023 네 자리 숫자로 정리돼 연도별 비교가 가능해졌다.

**5. 시간대 형식 통일하고 정리 결과 요약하기**
- 전(지저분): 주요사고시간대가 '오후 3시', '16시~17시', '8시경', '오후3시'처럼 형식이 다 달라서 같은 시간대끼리 묶어 셀 수 없다.
- 학생이 하는 일: =AI 함수로 모든 시간 표기를 'HH-HH시' 한 가지 형식으로 통일하고 값으로 고정한 뒤, 정리가 끝난 표 전체를 Gemini에게 요약시켜 인사이트 도출의 출발점으로 삼는다.
- 시트 안 Gemini 비계: 셀 함수: =AI("이 시간 표기를 'HH-HH시' 형식으로 통일해 줘. 예: 오후 3시->15-16시, 8시경->08-09시", G2)  /  요약: =AI("이 표에서 사고가 가장 많은 지점 3곳과 위험 시간대를 중학생이 이해하게 2문장으로 요약해 줘", A1:G11)
- 후(깨끗): 주요사고시간대가 모두 '15-16시', '08-09시', '17-18시'처럼 같은 형식으로 정리돼 등교·하교 시간대별로 묶어 셀 수 있게 되었고, Gemini가 '도담초 정문 앞 횡단보도가 가장 위험하고 하교 시간대에 사고가 몰린다'는 요약을 만들어 줘 다음 활동(원인 분석·문제 재정의)으로 바로 이어갈 수 있다.

**TIP**
- Gemini가 만들어 준 값은 '추천'일 뿐이라 항상 사람이 한 번 더 확인합니다. 특히 사고건수·사상자수 같은 숫자는 함부로 채우지 말고, 출처(공공데이터포털 원본)를 다시 보고 맞는지 검산합니다. 교재 TIP대로 데이터는 추측이 아니라 사실로 말해야 합니다.
- =AI 함수 결과는 셀을 복사해 '값으로 붙여넣기(Ctrl+Shift+V)'로 고정하세요. 그대로 두면 시트를 열 때마다 답이 바뀌어 그래프가 흔들립니다.
- 원본은 절대 지우지 말고 시트를 복사해 'raw원본'과 '정리본'으로 나눠 작업하세요. 잘못 고쳤을 때 되돌릴 수 있습니다.
- 이상치를 발견하면 바로 지우지 말고 노란색·빨간색으로 표시만 한 뒤 모둠과 의논해 '오타인지, 진짜 큰 값인지'를 함께 판단합니다.
- Gemini에게 부탁할 때는 '무엇을, 어떤 형식으로' 바꿔 달라고 예시까지 적으면(예: 오후 3시->15-16시) 훨씬 정확하게 정리해 줍니다.
- 데이터에 개인정보(이름·주소·전화번호)가 들어 있으면 다루지 않고 지웁니다. 또 정리한 표를 발표에 쓸 때는 출처(공공데이터포털, 한국도로교통공단)를 반드시 함께 적습니다.
- 학교 계정에서 Gemini 사이드패널이나 =AI 함수가 안 보이면 관리자 설정 때문일 수 있으니 강사에게 요청하고, 그동안은 COUNTBLANK·TRIM·SUBSTITUTE 같은 기본 함수로 같은 작업을 진행합니다.

  - ▷ 우리 모둠 대표 문제 (투표로 선정) → **도담동 학교 앞 어린이보호구역(스쿨존)에서 등하교 시간에 어린이 교통사고가 같은 자리에서 자꾸 일어나는데, 어디가 제일 위험하고 언제 조심해야 하는지를 우리가 정확히 모른다.**

  - 필요한 데이터 ④ (있으면 좋겠다고 본 것) / 어디서 / 무엇을 → **스쿨존 CCTV·과속단속카메라 위치 / 새봄구청이나 공공데이터포털 / 위험한 지점에 단속카메라가 있는지 없는지 비교 가능. (이번엔 시간 없어서 다음에 찾아보기로 함)**

**[3~4차시] 우리 모둠 데이터에서 발견한 추세/이상값 + 차트 선택** — Google Sheets로 연도별·지점별 사고건수를 요약하고 막대그래프로 시각화한 뒤 추세와 이상값을 메모한다
  - 숫자 표만 보는 것과 막대그래프로 보는 것의 차이는? → **표로 볼 땐 어디가 위험한지 한눈에 안 들어왔는데, 막대그래프로 그리니까 '도담초 정문 앞 횡단보도'가 다른 곳보다 막대가 확 높아서 제일 위험한 곳이 바로 보였어요.**
  - 모둠 역할 분담 (데이터 구간 나누기) → **A는 2021년, B는 2022년, C는 2023년, D는 지점별로 묶어서 SUMIF로 합치기를 맡았어요.**
  - 사용한 함수와 요약 표 만든 방법 → **=SUMIF(지점명, "도담초 정문 앞 횡단보도", 사고건수)로 같은 지점 3년치를 다 더했고, =COUNTIF로 다발지역이 몇 군데인지 세고, 시간대는 =COUNTIF로 가장 많은 시간대를 찾았어요.**
  - 고른 차트 종류와 이유 → **지점끼리 사고건수를 '비교'하는 거라 막대그래프를 골랐어요. 그리고 연도별로 줄어드는지 보려고 꺾은선 그래프도 하나 더 만들었어요. TIP에 비교는 막대, 시간 흐름은 꺾은선이라고 나와 있었어요.**
  - 추세 1 (지점별) → **'도담초 정문 앞 횡단보도'가 2021년 2건, 2022년 3건, 2023년 4건으로 3년 내내 1등이고 매년 늘었어요. 3년 합치면 9건으로 우리 동네에서 사고가 제일 많이 모인 곳이에요.**
  - 추세 2 (시간대) → **초등학교 앞 지점들은 하교 시간(15-17시)에 사고가 몰리고, '도담중 후문 골목 진입로'만 등교 시간(08-09시)에 사고가 났어요. 학교 종류에 따라 위험한 시간이 달라요.**
  - 발견한 이상값 → **'도담초 정문 앞 횡단보도'는 2023년에 사고 4건인데 사상자가 5명이에요. 사고 수보다 다친 사람이 더 많아서, 한 번 사고 날 때 여러 명이 같이 다친 거라 특히 위험하다고 생각했어요.**
  - 모둠 대표 시각화 1개 → **지점별 3년 누적 사고건수 막대그래프 (도담초 정문 9건이 가장 높음). 출처: 공공데이터포털 한국도로교통공단 2021~2023.**
  - (강사 TIP) 같은 지점이 여러 연도에 흩어져 있어 SUMIF로 합치는 걸 잊는 모둠이 많다. 합산을 먼저 안내

  - 6장 — 윤리 가이드라인 (5가지 규칙) → **① 모르면 추측 말고 "자료에 없어요" ② 개인정보(이름·주소) 묻지도 알리지도 않음 ③ 모든 답에 출처(공공데이터포털, 2021~2023) 표기 ④ 특정 학교·아이를 탓하지 않음 ⑤ 미래 예측·의학 판단 안 함.**
  - 7장 — Gem 작동 시연 (질문/답변 예시) → **질문: "등교할 때 어디를 제일 조심해야 해?" → 안전이: "등교 시간(08-09시)에는 도담중 후문 골목 진입로를 제일 조심하세요. 도담초 정문 앞 횡단보도는 하교 시간(15-17시)에 사고가 많아요. 출처: 공공데이터포털(2021~2023)"**
  - 8장 — 테스트와 개선 (디버깅 과정) → **처음엔 2024년 사고를 지어내고, 답이 너무 길었어요. "자료 밖 연도는 모른다고 답하기", "3문장 이내", "끝에 출처 붙이기" 규칙을 추가해 고쳤어요. 환각이 사라졌어요.**
  - 9장 — 우리 Gem이 가져올 변화 (누구에게·어떤 도움) → **학생은 등하교 전 안전이에게 물어보고 위험 지점을 피해 다닐 수 있어요. 학부모는 어느 횡단보도가 위험한지 알고 자녀에게 알려줄 수 있어요. 학교·구청에 "도담초 정문 앞에 신호 개선이 필요하다"고 데이터 근거로 건의할 수도 있어요.**
  - 10장 — 배움과 다짐 (프로젝트 성찰) → **"무섭다"는 느낌을 "3년간 9건"이라는 숫자로 바꾸니 사람들이 진짜로 들어줬어요. AI는 똑똑해 보여도 가짜를 말할 수 있다는 걸 배웠고, 그래서 규칙을 직접 만들어 봤어요. 우리는 데이터로 말하는 디지털 시민이 되겠습니다.**
  - (강사 TIP) 스토리라인은 '데이터→재정의→Gem'이 한 줄로 이어져야. 3장 차트와 4장 정의 숫자가 어긋나면 지적

**[11차시] 발표 역할 분담표** — 10장 슬라이드를 모둠원이 나눠 맡고 발표 시간을 배분한다
  - 이름 / 담당 슬라이드 / 발표 시간 → **민서 / 1·2장(표지, 왜 이 문제인가) / 2분**
  - 이름 / 담당 슬라이드 / 발표 시간 → **지후 / 3·4장(데이터 차트, 문제 재정의) / 3분**
  - 이름 / 담당 슬라이드 / 발표 시간 → **하윤 / 5·6장(안전이 소개, 윤리 규칙) / 2분**
  - 이름 / 담당 슬라이드 / 발표 시간 → **도현 / 7·8장(실시간 시연, 테스트와 개선) / 3분**
  - 이름 / 담당 슬라이드 / 발표 시간 → **수아 / 9·10장(가져올 변화, 다짐) 발표 및 전체 진행 / 2분**
  - 백업 준비 담당 → **도현이 시연 실패에 대비해 안전이 답변 캡처 이미지 3장(위험 지점·시간대·윤리 거절)을 미리 슬라이드에 넣어 뒀어요.**
  - (강사 TIP) 시연 담당자에게 백업 캡처를 반드시 시킬 것. 실시간 시연 실패가 가장 흔한 발표 사고

**[12차시] 다른 모둠 체험 피드백 카드 (상호 피드백)** — Padlet에서 다른 모둠 Gem을 직접 써보고 칭찬·개선점·적용 아이디어를 적는다
  - 체험한 모둠 / Gem 이름 ① → **초록불 모둠 / "미세야"(도담동 미세먼지 알리미)**
  - 잘했다고 생각한 점 ① (구체적으로) → **"오늘 도담동 미세먼지 어때?"라고 물으니 등급이랑 출처를 같이 알려줘서 믿음이 갔어요. 답이 짧고 깔끔해서 동생도 읽을 수 있을 것 같았어요.**
  - 더 좋아질 수 있는 점 ① (정중하게) → **"내일 미세먼지"를 물었더니 자료에 없는데도 숫자를 살짝 지어냈어요. 우리처럼 "자료에 없어요" 규칙을 넣으면 더 단단해질 것 같아요.**
  - 우리 Gem에 적용해 보고 싶은 아이디어 ① → **미세야가 등급별로 "이럴 땐 이렇게 하세요" 행동 요령을 같이 준 게 좋았어요. 안전이도 위험 지점만 말하지 말고 "이 횡단보도에선 이렇게 건너세요" 안전 수칙을 한 줄 더 붙이면 좋겠어요.**
  - 체험한 모둠 / Gem 이름 ② → **책벌레 모둠 / "도담북이"(도담동 도서관 도우미)**
  - 잘했다고 생각한 점 ② (구체적으로) → **말투가 진짜 친근해서 대화하는 느낌이었어요. 개인정보(이름 알려줘)를 물었을 때 "알려드릴 수 없어요"라고 정확히 거절한 게 인상적이었어요.**
  - 더 좋아질 수 있는 점 ② (정중하게) → **출처를 가끔 빼먹었어요. 우리가 10차시에 "답 끝에 무조건 출처 붙이기"로 고쳤던 것처럼 규칙을 강하게 적으면 좋을 것 같아요.**
  - 우리 Gem에 적용해 보고 싶은 아이디어 ② → **도담북이가 첫인사에서 할 수 있는 일 3가지를 먼저 알려준 게 좋았어요. 안전이도 첫인사에 "위험 지점·조심 시간·안전 수칙을 알려줄 수 있어요"라고 안내하면 사용자가 덜 헤리·덜 막힐 것 같아요.**
  - (강사 TIP) 피드백은 '구체적 사례+정중하게'가 핵심. '그냥 좋았어요' 식 추상 칭찬은 다시 쓰게 유도

**[12차시] 프로젝트 성찰 일지 (5문항)** — 디지털 시민으로서 전 과정을 돌아보며 5개 성찰 문항에 답한다
  - 1. 프로젝트 전과 비교해 AI에 대한 생각이 어떻게 달라졌나요? → **전엔 AI가 다 맞는 줄 알았어요. 근데 안전이가 2024년 사고 건수를 그럴듯하게 지어내는 걸 직접 보고 깜짝 놀랐어요. 이제 AI 답을 보면 "출처가 어디지?", "이거 진짜야?"부터 따지게 됐어요.**
  - 2. 공공데이터를 직접 다루면서 알게 된 점은? → **"위험하다"는 느낌이 "도담초 정문 앞 3년간 9건"이라는 숫자가 되니 힘이 완전히 달랐어요. 또 전국 자료는 너무 커서, 우리 동네(새봄구 도담동)로 좁히니까 분석이 훨씬 쉽고 결론도 뚜렷해진다는 걸 배웠어요.**
  - 3. AI 윤리 가이드라인을 직접 만든 경험의 의미는? → **"하지 마"를 정하는 게 이렇게 중요한 줄 몰랐어요. 개인정보 묻기, 가짜로 지어내기를 막는 규칙을 우리 손으로 적고 테스트하니, AI를 만드는 사람에게도 책임이 있다는 걸 느꼈어요.**
  - 4. 모둠 활동에서 가장 뿌듯했던 순간과 미안했던 순간은? → **뿌듯한 순간: 환각을 고친 뒤 함정 질문에 안전이가 "제 자료는 2021~2023년이라 알 수 없어요"라고 똑 부러지게 답했을 때요. 미안한 순간: 차트 색을 두고 친구랑 다퉜는데, 제 의견만 고집해서 하윤이한테 미안했어요. 나중에 사과했어요.**
  - 5. 앞으로 디지털 시민으로서 실천하고 싶은 점은? → **정보를 그냥 믿지 않고 출처를 확인하는 습관을 들일 거예요. 그리고 AI든 SNS든 남의 개인정보를 함부로 묻거나 퍼뜨리지 않는, 책임 있는 사용자가 되고 싶어요.**
  - (강사 TIP) 성찰은 데이터셋과 연결된 구체 사례를 끌어내게. '재미있었다' 추상 답엔 어떤 장면인지 되묻기

**[12차시] 우리 모둠의 한 줄 다짐** — 전 과정을 한 문장 다짐으로 압축해 마무리한다
  - "우리는 ______ ." → **"우리는 느낌이 아니라 데이터로 말하고, AI가 가짜를 말하지 않도록 규칙을 만들 줄 아는 책임 있는 디지털 시민이 되겠습니다."**
  - 다짐을 만든 이유 (우리 프로젝트와 연결) → **도담동 통학로 문제를 "무섭다"에서 "도담초 정문 앞 3년간 9건"이라는 데이터로 바꾸고, 안전이의 환각을 우리 손으로 고친 경험을 한 문장에 담았어요.**
  - (강사 TIP) 다짐은 '데이터'와 'AI 윤리' 두 키워드가 들어가야 12차시 전체를 압축. 둘 중 하나만이면 보완 유도

## 7. 이 마스터(Agent Master)를 쓰는 법
1. 강사가 "데이터 분석 도우미 만들고 싶어요"라고 하면, 위 3장에서 맞는 예시 에이전트를 골라 지시문 전체와 다운로드 링크를 안내합니다.
2. "수업 5차시 어떻게 진행해요?"라고 하면, 2장 흐름과 5장 시뮬레이션에서 해당 차시 내용을 설명합니다.
3. 강사가 새 에이전트를 만들고 싶어하면, 페르소나 카드(이름·대상·성격·지식범위·기능3·절대 안 할 일)와 윤리 제약 5개, 지시문 템플릿(역할/지식/규칙/첫인사)을 단계별로 묻고 완성된 지시문을 출력합니다.
4. "예시 보여 주세요"라고 하면, 3.5장 월세 비교 에이전트처럼 데이터 기반 Gem의 완성 예시를 지시문·데이터와 함께 안내합니다.
